# ATK X1 Pro Max

`atk-x1-pro-max` (`0.4.9-preview.1`) supports read-only battery telemetry plus preview DPI and polling-rate settings for the wired mouse (`373B:1017`) and its 8K receiver (`373B:101B`). Both verified upstream paths use interface 1, HID usage `FF02:0002`, report ID `08`, and 16-byte input/output payloads. The Windows HID buffer includes the report ID, so the driver requires 17-byte input and output reports and the `MI_01` interface path. It excludes the 1K receiver (`373B:101A`).

Before reading battery state, the driver sends identity command `10`. The reply must have command `10`, success status `00`, a valid report checksum, a declared three-byte payload, and CID/MID `02:27` (decimal `2,39`). Only then does it send battery command `04`. Its reply must have command `04`, status `00`, a valid report checksum, and exactly two declared data bytes: percentage (0–100) and charging (`00` or `01`). The other bytes in the captured report are padding and are ignored. Settings access is enabled only after exact identity confirmation. No pairing, lighting, or firmware operations are exposed.

The protocol implementation is independently written from public protocol facts. Source evidence is pinned to OpenMouse `mouse-protocol` commit [`bac031567b28f2a55c616fc525b03f2d5fa452cc`](https://github.com/OpenMouse-Project/mouse-protocol/tree/bac031567b28f2a55c616fc525b03f2d5fa452cc): [`docs/atk-testing.md`](https://github.com/OpenMouse-Project/mouse-protocol/blob/bac031567b28f2a55c616fc525b03f2d5fa452cc/docs/atk-testing.md) records verified X1 connections and settings captures; [`src/drivers/atk/hid.ts`](https://github.com/OpenMouse-Project/mouse-protocol/blob/bac031567b28f2a55c616fc525b03f2d5fa452cc/src/drivers/atk/hid.ts) documents the model-specific PAW3950 DPI and polling register operations. The exact identity is CID/MID `2,39` (ATK HUB maps it to X1 Pro Max).

The upstream repository is licensed under GNU AGPL v3; this crate uses protocol facts and source-backed settings layouts, with no copied implementation code. Writes are untested on this project’s hardware. DPI accepts 50–30,000 in 50-DPI steps; the source also documents 30,100–36,000 in 100-DPI steps, which this uniform-step host metadata does not expose. Polling accepts 125–8,000 Hz. EEPROM bytes are read before writing, then read back; if a write or verification fails, the driver attempts to restore and verify the original bytes. No button remapping, lighting, pairing or firmware operation is exposed.
