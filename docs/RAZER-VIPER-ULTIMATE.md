# Razer Viper Ultimate Wired Preview

Package: `razer-viper-ultimate-wired-driver` (`0.4.9-preview.1`). This plugin adapts public OpenRazer protocol facts; physical-device behavior has not been tested.

## Supported model and settings

- Wired USB Viper Ultimate only: VID/PID `1532:007A`. Wireless PID `007B` is excluded.
- The driver opens only one HID interface matching `MI_00`, a 91-byte Feature report, and the exact wired PID. The 91-byte Windows buffer includes a Report ID; no physical descriptor was captured. It sends no command if zero or multiple interfaces match.
- Reads battery, charging, DPI, polling rate, and logo brightness. It can set DPI from 100 to 20,000 in 50-DPI increments, polling rate at 125/500/1,000 Hz, and logo brightness from 0 to 255. Each setting is read before writing, verified afterward, and restored with readback verification if the write or check fails. DPI changes preserve other stages and unknown table bytes.
- The lighting editor writes upstream-supported static color, spectrum, reactive, and breathing logo effects. Brightness can be read from the mouse; current effect and color cannot. The app keeps the last configuration it successfully sent, and clearly labels it as saved app state rather than hardware readback. Button remapping and macros are not listed for this model and remain unavailable.
- Battery percent is derived from the device's 0–255 reading; charging values other than 0 or 1 are rejected. Hardware and firmware remain unverified.

## Protocol evidence

The implementation follows OpenRazer commit [`477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d`](https://github.com/openrazer/openrazer/tree/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d). Its [Viper Ultimate wired declaration](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/daemon/openrazer_daemon/hardware/mouse.py#L817-L840) lists DPI and stages (maximum 20,000), polling, battery, charging, logo brightness, logo effects, and custom frames. OpenRazer uses report index 0 and a 59,900 µs wait for this model ([driver path](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razermouse_driver.c#L32-L101), [wait constant](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razermouse_driver.h#L133)). The model's battery and charging commands use transaction ID `0xFF`; the DPI, stage, and polling handlers select the same ID ([DPI](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razermouse_driver.c#L2548-L2660), [stages](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razermouse_driver.c#L3162-L3253), [polling](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razermouse_driver.c#L1949-L2005)). LED brightness uses the extended-matrix commands with transaction ID `0x3F` ([handler](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razermouse_driver.c#L4280-L4385), [constructors](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razerchromacommon.c#L709-L741)). OpenRazer's shared constructors specify the DPI, stage, polling, battery, and charging command fields ([common protocol](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razerchromacommon.c#L1053-L1127), [DPI and stages](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razerchromacommon.c#L1211-L1325)). The report is 90 bytes and uses an XOR checksum ([layout](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razercommon.h#L124-L136), [checksum](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razercommon.c#L108-L124)).
