# Razer Viper V2 Pro Wired Preview

Package: `razer-viper-v2-pro-wired-driver` (`0.4.8-preview.1`). This is an independent adaptation of public OpenRazer protocol facts; it has not been tested with a physical Viper V2 Pro.

## Supported connection and settings

- Wired USB model only: VID/PID `1532:00A5`. Wireless PID `00A6` is excluded.
- The plugin opens only one matching interface with `MI_00` in its path and a 91-byte Feature report. It sends no request if zero or multiple interfaces match. The 91-byte Windows buffer includes the Report ID for OpenRazer's 90-byte wire structure. No physical descriptor was captured, so the path and length guards remain unverified.
- Reads battery, charging, current DPI, and polling rate independently; one unavailable setting does not discard the other readings.
- Supports DPI from 100 to 30,000 in 50-DPI increments and polling rates of 125, 500, or 1,000 Hz. Writes are sent once, then read back. A lost or mismatched readback is reported as unconfirmed and asks the host to refresh the device.
- When changing DPI, the plugin first reads the original DPI fields and full onboard DPI-stage table. It updates the active stage while preserving other stages and reserved bytes, then checks both readbacks. If either write or verification fails, it restores both original values and verifies the rollback. If it cannot understand the original table, it sends no write.
- OpenRazer lists DPI, DPI stages, polling rate, battery and charging methods for this model. It does not list button remapping or lighting methods here, so this plugin exposes neither.

## Protocol evidence

The source was checked at immutable OpenRazer commit [`477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d`](https://github.com/openrazer/openrazer/tree/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d). `mouse.py` defines `RazerViperV2ProWired`, VID `0x1532`, PID `0x00A5`, `DPI_MAX = 30000`, and the DPI, stage, polling, battery, and charging methods ([lines 1541–1555](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/daemon/openrazer_daemon/hardware/mouse.py#L1541-L1555)). The driver header assigns wired PID `0x00A5` and wireless PID `0x00A6` ([lines 88–89](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razermouse_driver.h#L88-L89)).

For the wired Viper V2 Pro, `razermouse_driver.c` uses transaction ID `0x1F` for battery, charging, DPI, DPI stages, and polling-rate commands; it uses the shared report-index-zero path ([report path lines 33–55](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razermouse_driver.c#L33-L55), [battery and charging lines 1624–1666 and 1741–1775](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razermouse_driver.c#L1624-L1666), [polling lines 1950–2000 and 2180–2220](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razermouse_driver.c#L1950-L2000), [DPI lines 2548–2575, 2769–2810, and stage handling lines 3162–3173 and 3278–3294](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razermouse_driver.c#L2548-L2575)). Its direct DPI query uses `NOSTORE` (`0`), and the default direct DPI write also uses `NOSTORE`; the DPI-stage query and write use `VARSTORE` (`1`). The plugin follows those model-specific selectors. The shared command constructors define battery (`0x07/0x80`), charging (`0x07/0x84`), polling (`0x00/0x85` read and `0x00/0x05` write), and DPI (`0x04/0x85` read and `0x04/0x05` write) ([battery and charging constructors](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razerchromacommon.c#L1053-L1070), [polling and DPI constructors](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razerchromacommon.c#L1092-L1127), [DPI constructors](https://github.com/openrazer/openrazer/blob/477f4d6d3ab7e9deb6310d5bd3742560c5cbe80d/driver/razerchromacommon.c#L1211-L1241)). Polling codes are `0x01`, `0x02`, and `0x08` for 1,000, 500, and 125 Hz. Battery is returned on a 0–255 scale; charging is 0 or 1.

This repository's AGPL-3.0-only license applies to the plugin and protocol crate. The DPI step and write/readback checks follow the pinned host SDK's existing Razer adapter behavior.
