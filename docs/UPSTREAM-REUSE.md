# 上游实现与设备证据的复用规则

本项目优先复用已公开、可追溯的协议实现和抓包。上游已验证的设备交互无需为了本项目再次实测；本机暂时没有目标设备，不会单独阻止开发或发布。每项功能仍须准确说明证据来源及本项目自己的验证状态。

## 能力证据按目标逐项记录

证据适用范围由**精确设备型号、连接方式、固件范围和具体操作**共同限定。PID、同品牌、同系列、共用接收器或代码相似都不能自行扩大范围。记录至少区分：

- **上游硬件证据**：是否有目标设备的真实抓包或明确硬件报告；覆盖了什么读取/写入，哪些字段回读、恢复成功，及设备/连接/固件信息。
- **上游实现证据**：固定仓库提交、具体源码/测试/捕获文件，以及许可证。协议单元测试或模拟回复可佐证编码规则，但不能改写为真实硬件验证。
- **本项目移植状态**：Windows HID 与 ABI 的映射、功能集成、包安装与升级的数据保留是否已检查。本项目没有做过的本机硬件验证必须如实标为“未在本项目实机验证”。

能力只在上游明确覆盖的范围内声明。设备或固件不确定时缩小适用范围并标出未知；协议、身份或操作仍无可靠依据时，只能保留为研究项，不能把未知写成兼容、可读或可写。

## 开发与验收边界

当固定上游资料已验证精确目标上的某项操作，允许按该资料复用代码或独立移植协议，包括写操作；不额外要求本项目先拥有设备或重复验证上游协议。发布前检查实际移植产生的差异：Windows HID 的集合、报告 ID 和缓冲区语义，ABI/manifest 能力声明，输入输出边界，以及包集成。针对写入，应沿用有依据的事务和数据保留语义，不把读能力当成写能力，也不把某设备的验证外推到其他设备。

安装或升级另做软件级数据保留验收：保存升级前的用户配置、设备设置或由本项目管理的数据，对照升级后的结果，确认未丢失、清空或覆盖。此检查针对本项目的安装/升级路径，不要求用硬件重演上游协议抓包。只有移植改动引入了上游未覆盖的设备差异时，才为该差异另立验证项；不要把无关的防御性复测加入每项接入。

## 来源与许可

固定上游仓库和提交，链接到对应文件与证据，检查实际拟复用文件的许可证。复制代码时保留版权、许可证和修改声明，并满足适用的源码提供义务；仅使用协议事实另写实现，也应注明来源和型号依据。该仓库当前核查点为 OpenMouse Project `mouse-protocol` 提交 [`bac031567b28f2a55c616fc525b03f2d5fa452cc`](https://github.com/OpenMouse-Project/mouse-protocol/tree/bac031567b28f2a55c616fc525b03f2d5fa452cc)，仓库许可证为 GNU AGPL v3。本项目发行许可与具体复用文件应一并审查并记录在包许可清单中。

## 当前候选如何应用

- MCHOSE MagDock：固定资料记录 `3837:1012` 底座的真实读取、灯效写入/读回和恢复；足以作为该底座灯效移植依据。本项目只需核对 Windows/ABI/包边界及安装数据保留，并标注未在本项目实机验证。
- AJAZZ AJ179 PRO：固定资料记录鼠标固件 v3.03 下接收器、USB、蓝牙三条连接路径的设置与按键读写/读回，并给出配置恢复结果。按对应路径移植，不从其结果推广至其他 AJAZZ 型号。
- MCHOSE A7 V3：固定资料当前明确读操作有硬件记录、写操作从未在硬件发送。因此可以复用其已证实的读取能力，暂不把设置写入声明为已验证能力；这项限制来自上游证据缺口，不来自本项目是否持有设备。
