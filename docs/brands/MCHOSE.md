# MCHOSE / 迈从

当前包：`mchose-a5-ultra`（初代）、`mchose-g75-pro`。状态以各包 manifest.validation 及既有实机记录为准，不把全品牌统称兼容。

A5 初代：3837:100C、FF01 vendor集合、精确产品名；M HUB 取反 Feature 协议。电量按已实现的响应字段 `body[9]` 直接读取整数百分比，不换算；查询前清空旧完成通知，读不到当前回复就显示缓存/错误。Vigil Watt v1.3.0 的 `3837:100C` 条目明确是 A5 V2 Ultra，不能作为初代证据。初代电竞开关与新版三态性能模式、宏页格式均须区分。G75 Pro：3554:FA09、FF02集合，键盘性能/按键/灯色分块协议，不能沿用鼠标报文。电量回复 `13 4A 01 …` 的第 `[5]` 字节直接为整数百分比；Vigil Watt 记录贡献者报告的样本 `0x24 = 36%`，0–1 为占位值。厂商号相同不等于协议相同。

上游线索：OpenMouse 的 a5-gen1 与新版 MCHOSE 分离、M HUB 本轮固定本地取样；不能借 A7 V2 Ultra+ 的实测结论覆盖初代 A5。A5 当前固件未能返回可完整备份的原宏页时，保持拒写。未来型号先读身份/电量，再补设置回读与恢复。

完整来源与许可证见 [调查矩阵](../PROTOCOL-RESEARCH.md)。

V9 Pro 新增独立电量预览包：仅 `291D:385D` 接收器 `MI_00/COL05` 的 `FF90:0001`、64 字节电量 collection。查询会主动发送 `55 65 01`，安装预览包即授权轮询。Vigil Watt v1.3.0 只记录贡献者单台设备的 100% 样本；本项目未实测，充电状态与非满电映射未知。详见[验证范围](../MCHOSE-V9-PRO.md)。
